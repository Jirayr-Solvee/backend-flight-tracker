# Sofly 3.7 backend tracking audit — September 5, 2026

Audited baseline `4e5874e` including experiment revision `6522883`, plus the local
changes described below. This is source, database, and local HTTP evidence. No
production writes, real purchases, or AppsFlyer raw-data reads were performed in
this backend audit.

## Corrections from this audit

1. Verified Apple transaction/revenue/entitlement facts commit before experiment
   metadata. A cohort conflict now returns HTTP 200 with
   `experiment_tracking_status=conflict`; a transient metadata failure returns
   `pending`. Neither means payment failure. Retrying the same original metadata
   after a transient failure recovers conversion attribution without creating
   another verified transaction.
2. App registration and App Store notifications share atomic SQLite upserts
   guarded by Apple's signed date. An equal-date verified refund may enrich a
   transaction; older/equal unrevoked retries cannot remove its refund. This
   protection is evaluated by the database, including when an independent session
   has already loaded an older unrevoked object.
3. Entitlement cache refresh derives the current transaction per linked
   subscription, considering a relevant current billing grace window. Replaying an
   old initial transaction or its refund cannot replace a newer renewal's expiry.
   Same-snapshot registration still refreshes the cache and supports a restore.
4. Conversion cohort app version/build now come from revision-2 enrollment when
   present, even if its paywall is presented after an app update. The conversion
   version is stored separately.
5. Backend diagnostics now retain bounded discovery/onboarding facts, alternative
   plan reveals, flight-add failures, metadata-registration outcomes, random
   search-journey/session IDs, attempt numbers, and plan/result counts. The report
   joins selection/add/detail flight IDs by journey. Raw searches, normalized
   searches, freeform errors, identity tokens, and notification bodies remain
   outside this allowlist.
6. A freshly re-signed expired transaction cannot erase an independent billing
   grace period. Lifecycle selection filters the current transaction and actual
   entitlement state before ordering: an older renewal's later refund, or an
   informational consumption request with no renewal info, cannot mask current
   grace. A later authoritative grace expiration still ends access. Unknown/null
   signature freshness cannot erase a known refund.
7. Partial refunds use Apple's integer **milli-percent** scale (50,000 = 50%,
   100,000 = 100%), consistently in the experiment and Apple Ads reports. Zero is
   distinct from absent legacy full-refund metadata. The pinned Apple SDK 2.0.0
   drops this additive field, so a narrow adapter preserves it from the exact JWS
   only **after** SDK signature/bundle/environment verification succeeds. No raw
   JWS is persisted or logged by this adapter. Scale source:
   [Apple revocationPercentage](https://developer.apple.com/documentation/appstoreservernotifications/revocationpercentage).

```bash
  tests.test_service_readiness
.venv/bin/python -m compileall -q core
git diff --check
```

Result: **80 tests passed**, compile and whitespace checks passed. Existing test
fixtures produce expected injected-error logs and occasional SQLite resource
warnings; no test failure remained. Authentication tokens used by tests are dummy
fixture values and were not printed.
